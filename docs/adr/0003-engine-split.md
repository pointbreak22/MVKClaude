# ADR 0003: где проходит граница Engine / Engine.Client

Статус: принято (2026-11-12), этап 2.

## Контекст
В Vge серверная логика, логика клиента и рендер перемешаны: `EntityBase` создаёт свои
`EntityRender*` через `EntitiesRenderer`, `BlockBase` хранит `BlockRenderFull` (мешинг чанка),
реестры получают `WindowMain`, `WorldClient`/`PlayerClientOwner`/`ProcessClientPackets` держат
`GameBase`, а тот наследует окно (`Warp`) и владеет `WorldRenderer`, HUD и клавиатурой WinGL.
Карта зависимостей (скрипт в журнале этапа 2): 50 серверных файлов используют клиентские типы.

## Решение
Граница проходит не между «сервером» и «клиентом», а между **логикой** и **представлением**.

- `Mvk.Engine` — сервер, общие правила игры и **логика клиента** (headless-клиент):
  мир клиента, приём пакетов, предсказание движения игрока, руки, инвентарь, частицы как данные.
  Никаких окон, GL, звука, шрифтов, GUI.
- `Mvk.Engine.Client` — представление: окно и ввод (через `Mvk.Platform`), RHI-рендер, меши чанков,
  рендер сущностей, GUI, звук.

Почему так: headless-клиент можно гонять в тестах (сервер + клиент в одном процессе без окна),
он же пригодится для ботов и для телефона/Vulkan без копирования логики.

## Швы (интерфейсы в Engine, реализации в Engine.Client)
1. **Рендер сущностей.** `EntityRenderBase` (пустой, серверный) остаётся в Engine. Подклассы
   (`EntityRenderClient`, `...Animation`, `...EyeMouth`, `...Item`, `...Particle`) уходят в клиент.
   Создание через `IEntityRenderFactory`, который клиент передаёт в `InitRender`.
2. **Рендер блоков.** `BlockBase.BlockRender` заменяется ключом типа рендера; клиент сопоставляет
   ключ с `BlockRenderFull`/`BlockRenderLiquid`/своими рендерами мода. `Gi.BlockRend*` уходят в клиент.
3. **Чанки клиента.** Логика (`ChunkClient : ChunkBase`) в Engine, меши (`ChunkRender : ChunkClient`)
   в клиенте; `ChunkProviderClient` создаёт чанки через фабрику.
4. **Игра клиента.** `GameBase` делится на логику (Engine: мир, игрок, пакеты, такты) и хост
   (клиент: окно, HUD, `WorldRenderer`, звук). Логика получает `IGameClientHost` (время кадра,
   звук, частицы, захват мыши, остановка).
5. **Ввод.** Клавиши WinGL (`Keys`, `MouseButton`) не попадают в Engine: логика получает
   действия `InputAction`, раскладка клавиш живёт в клиенте/платформе.
6. **Реестры.** `Initialization(WindowMain)` → `Initialization(IProgress<…>)`; загрузка текстур
   в видеокарту (`InitializationAtlas`, `SetImageTexture2dArray`) — отдельный шаг клиента.
7. **Картинки.** `BufferedImage` (System.Drawing, только Windows) → простой `ImageRgba`
   (ширина, высота, байты) в Engine; декодер PNG на стороне клиента/платформы.
8. **Debug и Options.** Статистика и игровые настройки — Engine; рисование отладки и раскладка
   клавиш — клиент.

## Последствия
- Сигнатуры, которые переопределяет мод (Mvk2), меняются в нескольких местах:
  `InitRender`, `_InitBlockRender`, методы предметов с `PlayerClientOwner`. Мод переносится на этапе 3
  с теми же изменениями.
- Порядок работ этапа 2: сначала швы 1, 2, 6, 7, 8 (сервер компилируется), затем 3, 4, 5 (клиентская логика).
- `ArchitectureTests` продолжают запрещать Engine ссылки на Rendering/Platform/Silk.NET.
