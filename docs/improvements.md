# Улучшения, найденные при переносе

Правило: при каждом переносе ищем, где код можно сделать чище архитектурно и быстрее.
Нейтральные к поведению улучшения применяются сразу; меняющие поведение помечаются `[ПОВЕДЕНИЕ]`
и вносятся отдельным коммитом только после проверки golden-тестами.

Статусы: **сделано**, **отложено** (ждёт переноса мест использования), **предложено**.

## Математика (`WinGL/Util` → `Mvk.Core.Maths`)

| # | Что было | Что сделано / предлагается | Статус |
|---|----------|----------------------------|--------|
| M1 | Таблицу синусов `Glm` заполняет `WinGL.Window` через `Glm.Initialized()`. Без окна (сервер, тесты) `Sin/Cos` возвращают 0. Это скрытая зависимость порядка инициализации. | Таблица заполняется `static readonly` инициализатором той же формулой; `Initialized()` удалён. Результаты побитно те же (math.csv). | сделано |
| M2 | `Equals(object)` и `==` у векторов шли через боксинг; `GetHashCode` — XOR полей (`(1,2)` и `(2,1)` давали одинаковый хэш, плохо для словарей координат чанков). | `IEquatable<T>`, `==` без боксинга, `HashCode.Combine`. Хэши не сохраняются в файлы, поведение не меняется. | сделано |
| M3 | `Mat4` — struct, но внутри массив `Vector4[]` в куче: каждая матрица — аллокация, а копия struct разделяет массив с оригиналом (изменение копии меняет оригинал). | Переделать в настоящий value-type (16 float полей или `System.Numerics.Matrix4x4`) при переносе мест использования (камера, рендер, модели). Проверить, не опирается ли код на алиасинг. | отложено |
| M4 | `Mat4.ToArray()` / `Mat3.ToArray()` выделяют новый массив на каждый вызов, вызываются каждый кадр для uniform-ов. | В RHI передавать матрицу через `Span<float>`/`ref` без аллокаций. | отложено (этап 4, рендер) |
| M5 | `Mth` был обычным классом со статическими методами. | `static class`. | сделано |
| M6 | `throw new Exception(Sr.OutOfRange)` в индексаторах (зависимость математики от глобальных строк игры). | `ArgumentOutOfRangeException(nameof(index))`. | сделано |
