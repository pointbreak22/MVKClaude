# MvkClaude: кроссплатформенный порт «Малювекi 2»

Этот файл читается в начале каждой сессии Claude. Держите его коротким и актуальным.
Подробности хода работ ведутся в `docs/progress.md`, архитектурные решения в `docs/adr/`.

## Цель
Перенести игру «Малювекi 2» (движок Vge + контент Mvk2) на кроссплатформенный стек
(Windows / Linux / macOS, затем Android и iOS), **сохранив игровую механику 1:1**:
генерацию мира, мобов, предметы, физику, внешний вид. Улучшения и оптимизации
допустимы, но каждое изменение поведения фиксируется в `docs/progress.md`
с пометкой `[ПОВЕДЕНИЕ]`.

## Исходник (источник истины)
- Репозиторий: https://github.com/SuperAnt30/Vge, базовый коммит `dfbd814` (11.11.2026).
- Локальная копия оригинала: `original/` (отдельный git-клон, в .gitignore; только чтение, не редактировать).
- Соответствие «старый файл → новый проект» ведётся в `docs/migration-map.md`.

## Стек
- .NET 10 (LTS), C# latest, `<Nullable>enable</Nullable>` в новом коде.
- Окно, ввод, GL/Vulkan, OpenAL: **Silk.NET**.
- Рендер через собственный слой абстракции `Mvk.Rendering` (RHI). Первый бэкенд —
  OpenGL 3.3 core / GLES 3.0, второй — Vulkan.
- Avalonia допускается только для лаунчера и инструментов, не для игрового цикла.

## Структура решения
```
src/
  Mvk.Core/               математика (бывш. WinGL.Util.Glm/Mth), утилиты, NBT, JSON; без зависимостей от платформы
  Mvk.Engine/             мир, чанки, генерация, сущности, предметы, сеть, команды, сервер; без графики
  Mvk.Engine.Client/      клиентская логика: мешинг чанков, камера, частицы, GUI-логика, звук через интерфейсы
  Mvk.Rendering/          RHI: интерфейсы буферов, шейдеров, текстур, пайплайнов
  Mvk.Rendering.OpenGL/   бэкенд GL 3.3 / GLES 3.0
  Mvk.Rendering.Vulkan/   бэкенд Vulkan (позже)
  Mvk.Platform/           Silk.NET: окно, ввод, аудио, файловая система
  Mvk.Game/               контент Mvk2: блоки, предметы, биомы, ИИ мобов (серверная часть)
  Mvk.Game.Client/        клиент Mvk2: небо, HUD, экраны, рендер сущностей
  Hosts/Mvk.Desktop/      exe для ПК
  Hosts/Mvk.Android/      (позже)
  Hosts/Mvk.Server/       выделенный сервер без графики
tests/
  Mvk.Core.Tests/  Mvk.Engine.Tests/  Mvk.Game.Tests/  Mvk.Platform.Tests/ (платформа и RHI)
assets/                   ресурсы из res/Assets (копируются в вывод сборки)
```

## Правила зависимостей (нарушать нельзя)
- `Core` ни от чего не зависит.
- `Engine` и `Game` не ссылаются на `Rendering*`, `Platform`, `*.Client`.
  Сервер обязан собираться и работать без графики.
- `*.Client` знают только `Mvk.Rendering` (интерфейсы), но не конкретный бэкенд.
- Конкретный бэкенд выбирает только хост (`Hosts/*`).
- Ввод идёт через действия (`InputAction`), а не через клавиши. Это нужно для
  управления двумя руками и для сенсорного экрана.

## Стиль кода (из оригинала, res/Coding standard.txt)
- Локальные переменные: `camelCase`.
- private/protected поля: `_camelCase`.
- private/protected методы и константы: `_PascalCase`.
- Всё остальное: `PascalCase`.
- Комментарии и XML-doc на русском.
- Без закомментированного мёртвого кода: история хранится в git.
- В горячих путях (тик, кадр, мешинг) никаких аллокаций: пулы, `Span<T>`, `ArrayPool`.

## Команды
- Сборка: `dotnet build MvkClaude.slnx -c Debug`
- Тесты: `dotnet test MvkClaude.slnx`
- Запуск ПК: `dotnet run --project src/Hosts/Mvk.Desktop` (заставка, главное меню, игра;
  `-- --screenshot кадр.png --shot-after 8` сразу запускает одиночную игру, сохраняет кадр и выходит,
  им проверяется рендер без человека; `--menu`, `--screen chat|inventory|pause`, `--cmd "/time n"`, `--look`, `--view`;
  `--mouse original` кнопки мыши в мире как в оригинале (по умолчанию правая ломает, левая ставит);
  `--test-scene` тестовая сцена RHI этапа 4)
- Сервер: `dotnet run --project src/Hosts/Mvk.Server`

## Проверка паритета с оригиналом
- `tests/Mvk.Game.Tests/Golden/` хранит хэши чанков, снятые со старого генератора
  (seed + координаты → хэш блоков). Новый генератор обязан совпадать.
- Перед изменением генерации, физики или ИИ прогонять golden-тесты.
  Расхождение допустимо только как осознанное `[ПОВЕДЕНИЕ]`-изменение.

## Порядок работы
1. Брать следующий этап из `docs/plan.md`.
2. Переносить по одному модулю, сразу с тестами.
3. После каждого шага обновлять `docs/progress.md` (что сделано, что дальше)
   и `docs/migration-map.md`.
4. Известные баги оригинала (см. `docs/known-issues.md`) исправлять отдельными коммитами.
5. **При каждом переносе анализировать, где код можно сделать чище архитектурно и быстрее**
   (аллокации в горячих путях, боксинг, глобальное состояние, скрытый порядок инициализации,
   лишние копии). Каждую находку записывать в `docs/improvements.md`:
   нейтральные к поведению — применять сразу; меняющие поведение — помечать `[ПОВЕДЕНИЕ]`
   и применять только отдельным коммитом после проверки golden-тестами.

## Где что лежит
- `docs/plan.md` — этапы переноса 0–10 с критериями готовности.
- `docs/progress.md` — журнал: что сделано, что дальше. **Обновлять после каждого шага.**
- `docs/migration-map.md` — какие папки оригинала куда переезжают и их статус.
- `docs/improvements.md` — найденные при переносе улучшения архитектуры и производительности.
- `tools/GoldenGen` — утилита: собирает оригинал без изменений и снимает эталоны (`island`, `math`).
- `docs/known-issues.md` — найденные баги оригинала (исправлять отдельно, с пометкой `[ПОВЕДЕНИЕ]`).
- `docs/adr/` — архитектурные решения (почему Silk.NET, как устроен RHI и т.д.).
- `tests/Mvk.Engine.Tests/ArchitectureTests.cs` — автоматически проверяет правила зависимостей.
